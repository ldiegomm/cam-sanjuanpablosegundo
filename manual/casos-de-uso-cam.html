1. Objetivo del documento

Este documento describe los principales casos de uso del sistema del Centro Adulto Mayor San Juan Pablo II desde la perspectiva del usuario. Los flujos fueron derivados de las pantallas, validaciones, permisos y acciones disponibles actualmente en la aplicacion.

Los casos de uso se centran en acciones de usuario final y administrador. Los procesos automaticos del sistema, como reportes diarios y respaldos semanales, no se modelan aqui como casos de uso de usuario porque no son disparados manualmente desde la interfaz.

2. Actores del sistema

Actor Descripcion Capacidades principales
Colaborador Usuario operativo del centro con acceso al sistema. Iniciar sesion, consultar panel, gestionar adultos mayores, medicamentos e historial de salud.
Administrador Usuario con acceso completo a funciones operativas y administrativas. Todas las capacidades del colaborador mas la administracion de usuarios del sistema.
Sistema Aplicacion web y servicios backend. Validar credenciales, guardar informacion, controlar permisos y mostrar mensajes de confirmacion o error.

4. Casos de uso detallados

CU-01. Iniciar sesion

Actor principal: Colaborador o Administrador

Objetivo: Acceder al sistema con credenciales validas.

Precondiciones: El usuario posee correo y contrasena registrados y se encuentra activo.

Disparador: El usuario abre la pantalla de login y presiona "Iniciar sesion".

Flujo principal:

  1. El usuario ingresa su correo electronico.
  2. El usuario ingresa su contrasena.
  3. El sistema valida formato basico y credenciales.
  4. El sistema crea la sesion y redirige al panel de inicio.

Flujos alternos:

  • Si el correo no es valido, el sistema muestra: "Ingresá un correo electrónico válido."
  • Si el correo o la contrasena son incorrectos, el sistema muestra: "Correo o contraseña incorrectos. Verificá tus datos e intentá de nuevo."
  • Si ocurre un problema de red, el sistema muestra: "Error de conexión. Verificá tu conexión a internet e intentá de nuevo."

Postcondiciones: El usuario autenticado queda en la pantalla /home con sesion activa.

CU-02. Recuperar contrasena

Actor principal: Colaborador o Administrador

Objetivo: Solicitar un enlace para restablecer la contrasena.

Precondiciones: El usuario conoce el correo con el que fue registrado.

Disparador: El usuario selecciona "¿Olvidaste tu contraseña?".

Flujo principal:

  1. El usuario ingresa su correo en la pantalla de recuperacion.
  2. El usuario presiona "Enviar link de recuperación".
  3. El sistema procesa la solicitud y muestra la pantalla de confirmacion.
  4. El usuario revisa su correo y usa el enlace recibido.

Flujos alternos:

  • Si hay error de conexion, se informa al usuario.
  • Si el enlace es invalido o expira, el flujo debe reiniciarse desde la solicitud de recuperacion.

Postcondiciones: El sistema deja al usuario listo para definir una nueva contrasena.

CU-03. Cerrar sesion

Actor principal: Colaborador o Administrador

Objetivo: Finalizar la sesion activa de forma segura.

Precondiciones: El usuario se encuentra autenticado.

Disparador: El usuario presiona "Salir" o "Cerrar sesión".

Flujo principal:

  1. El sistema pregunta: "¿Estás seguro que querés cerrar sesión?"
  2. El usuario confirma la accion.
  3. El sistema elimina la sesion y redirige al login.
  4. El sistema muestra el mensaje "Sesión cerrada correctamente."

Flujos alternos: Si existen cambios sin guardar en formularios, el sistema primero solicita confirmacion para descartar cambios.

Postcondiciones: La sesion queda cerrada y el usuario vuelve a la pantalla de acceso.

CU-04. Consultar panel de inicio

Actor principal: Colaborador o Administrador

Objetivo: Visualizar el resumen diario del centro y los medicamentos programados.

Precondiciones: El usuario inicio sesion correctamente.

Disparador: El sistema redirige a /home o el usuario selecciona "Inicio".

Flujo principal:

  1. El sistema carga el total de personas registradas.
  2. El sistema calcula quienes tienen medicamentos hoy.
  3. El sistema muestra el total de dosis programadas.
  4. El sistema lista los medicamentos del dia por paciente y momento de toma.

Flujos alternos:

  • Si no hay medicamentos para el dia, se muestra: "No hay medicamentos programados para hoy."
  • Si la carga falla, aparece una pantalla de error con accion "Reintentar".

Postcondiciones: El usuario obtiene un panorama actualizado del dia.

CU-05. Registrar adulto mayor

Actor principal: Colaborador o Administrador

Objetivo: Crear un nuevo registro de adulto mayor en el sistema.

Precondiciones: El usuario tiene sesion activa y permisos operativos.

Disparador: El usuario presiona "+ Nuevo registro" en el modulo Adultos.

Flujo principal:

  1. El usuario completa nombre, cedula, fecha de nacimiento y sexo.
  2. Opcionalmente agrega telefono, estado civil, pension IVM, direccion y datos de contacto.
  3. El usuario presiona "Guardar registro".
  4. El sistema valida los datos y almacena el nuevo registro.
  5. El sistema muestra: "Registro guardado exitosamente." y redirige al listado.

Flujos alternos:

  • Si faltan campos obligatorios, el sistema informa: "Los campos Nombre, Cédula, Fecha de nacimiento y Sexo son obligatorios."
  • Si falla la persistencia, se muestra un error de guardado o de conexion.

Postcondiciones: Existe un nuevo adulto mayor disponible para consulta, historial y medicamentos.

CU-06. Consultar y editar perfil de adulto mayor

Actor principal: Colaborador o Administrador

Objetivo: Revisar o actualizar la informacion de un paciente.

Precondiciones: El paciente existe en el sistema.

Disparador: El usuario selecciona "Ver" en la lista y luego "Editar" si desea modificar datos.

Flujo principal:

  1. El sistema muestra el perfil completo del paciente.
  2. El usuario revisa datos personales, direccion, familiar solicitante y contacto de emergencia.
  3. Si desea editar, abre el formulario correspondiente.
  4. Modifica los campos necesarios y presiona "Guardar cambios".
  5. El sistema confirma con "Registro actualizado exitosamente."

Flujos alternos:

  • Si el paciente fue eliminado o no existe, se muestra el estado "Paciente no encontrado".
  • Si el usuario abandona el formulario con cambios pendientes, el sistema muestra el modal de cambios sin guardar.

Postcondiciones: La informacion del paciente queda actualizada si el guardado fue exitoso.

CU-07. Eliminar adulto mayor

Actor principal: Colaborador o Administrador

Objetivo: Eliminar un paciente junto con su historial y medicamentos asociados.

Precondiciones: El paciente existe y el usuario confirma la accion.

Disparador: El usuario presiona "Eliminar" en la lista de adultos.

Flujo principal:

  1. El sistema muestra una advertencia de eliminacion irreversible.
  2. El usuario selecciona "Sí, eliminar".
  3. El sistema elimina el registro y sus dependencias.
  4. El sistema informa: "[nombre] fue eliminado correctamente."

Flujos alternos:

  • Si el usuario cancela, no se realiza ninguna accion.
  • Si falla la operacion, se muestra un mensaje de error y el registro permanece.

Postcondiciones: El paciente deja de estar disponible en el sistema si la eliminacion fue exitosa.

CU-08. Gestionar medicamentos

Actor principal: Colaborador o Administrador

Objetivo: Registrar, consultar, editar o eliminar medicamentos asociados a un paciente.

Precondiciones: El usuario selecciono previamente a un adulto mayor.

Disparador: El usuario entra al modulo "Medicamentos" y elige un paciente.

Flujo principal:

  1. El usuario busca y selecciona una persona.
  2. El sistema muestra sus prescripciones existentes.
  3. El usuario puede agregar un medicamento con nombre, dosis, indicaciones, horarios y dias.
  4. El usuario puede editar o eliminar un medicamento existente.
  5. El sistema confirma cada alta, actualizacion o eliminacion.

Flujos alternos:

  • Si no hay persona seleccionada, el sistema no permite agregar medicamentos.
  • Si falta el nombre del medicamento, el sistema rechaza el formulario.
  • Si no se define una combinacion valida de dias, el sistema solicita corregirla.

Postcondiciones: La pauta de medicacion del paciente queda actualizada.

CU-09. Consultar y actualizar historial de salud

Actor principal: Colaborador o Administrador

Objetivo: Mantener la informacion clinica basica de cada adulto mayor.

Precondiciones: Existe un paciente seleccionado en el modulo Historial.

Disparador: El usuario accede al modulo "Historial" y selecciona una persona.

Flujo principal:

  1. El sistema muestra padecimientos, lesiones, habitos y operaciones del paciente.
  2. El usuario selecciona "Editar historial".
  3. El usuario modifica la informacion requerida.
  4. El usuario presiona "Guardar cambios".
  5. El sistema confirma con "Historial actualizado correctamente."

Flujos alternos:

  • Si no existe historial previo, el sistema muestra un estado vacio y permite comenzar la carga.
  • Si el usuario intenta salir con cambios pendientes, se activa el control de cambios sin guardar.

Postcondiciones: El historial del paciente refleja la ultima informacion guardada.

CU-10. Administrar usuarios del sistema

Actor principal: Administrador

Objetivo: Crear, editar, activar, desactivar o eliminar cuentas de acceso.

Precondiciones: El usuario autenticado posee rol admin.

Disparador: El administrador presiona el icono de configuracion para abrir "Usuarios del sistema".

Flujo principal:

  1. El sistema muestra la lista de usuarios registrados.
  2. El administrador selecciona "+ Nuevo usuario" o "Editar".
  3. Completa nombre, apellidos, correo, rol y estado.
  4. Si se trata de un alta, define una contrasena inicial.
  5. El sistema guarda la informacion y confirma la accion.

Flujos alternos:

  • Si faltan datos requeridos, el sistema bloquea el guardado.
  • Si la contrasena es demasiado corta, se informa al administrador.
  • El sistema impide dejar la aplicacion sin al menos un usuario administrador.
  • El usuario autenticado no puede eliminarse a si mismo desde el modal.

Postcondiciones: La configuracion de accesos queda actualizada segun la operacion ejecutada.

CU-11. Buscar y seleccionar pacientes

Actor principal: Colaborador o Administrador

Objetivo: Localizar rapidamente a un adulto mayor para ver o modificar su informacion.

Precondiciones: Existen pacientes cargados en el sistema.

Disparador: El usuario usa el buscador de Adultos, Historial o Medicamentos.

Flujo principal:

  1. El usuario escribe parte del nombre o la cedula.
  2. El sistema filtra o despliega coincidencias en tiempo real.
  3. El usuario selecciona el paciente deseado.
  4. El sistema carga el contexto asociado al modulo actual.

Flujos alternos: Si no existen coincidencias, se muestra un estado vacio o un mensaje equivalente a que no hay resultados.

Postcondiciones: El paciente queda seleccionado para la siguiente operacion.

CU-12. Navegar entre modulos con control de cambios sin guardar

Actor principal: Colaborador o Administrador

Objetivo: Cambiar de pantalla sin perder informacion por accidente.

Precondiciones: El usuario tiene un formulario de adultos o historial con cambios pendientes.

Disparador: El usuario intenta volver, cambiar de modulo o cerrar sesion.

Flujo principal:

  1. El sistema detecta que hay cambios sin guardar.
  2. El sistema muestra el modal "Cambios sin guardar".
  3. El usuario elige "Quedarme" o "Salir sin guardar".
  4. Segun la eleccion, el sistema conserva la edicion actual o continua la navegacion solicitada.

Flujos alternos: Si no existen cambios pendientes, la navegacion ocurre de inmediato sin modal.

Postcondiciones: El usuario conserva el control sobre sus cambios antes de abandonar la pantalla actual.

5. Reglas generales del sistema

  • Solo usuarios autenticados pueden ingresar a los modulos principales.
  • Solo los administradores pueden gestionar usuarios.
  • La eliminacion de adultos mayores y usuarios requiere confirmacion explicita.
  • La sesion se maneja mediante cookie segura y el sistema actualiza el ultimo acceso al iniciar sesion.
  • Los formularios criticos detectan cambios sin guardar para evitar perdida accidental de informacion.
  • El panel de inicio se actualiza automaticamente y usa la logica diaria de medicamentos del sistema.
