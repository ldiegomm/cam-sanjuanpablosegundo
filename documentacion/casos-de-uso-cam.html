1. Objetivo del documento

Este documento describe los principales casos de uso del sistema del Centro Adulto Mayor San Juan Pablo II desde la perspectiva del usuario. Los flujos fueron derivados de las pantallas, validaciones, permisos y acciones disponibles actualmente en la aplicación.

Los casos de uso se centran en acciones de usuario final y administrador. Los procesos automáticos del sistema, como reportes diarios y respaldos semanales, no se modelan aquí como casos de uso de usuario porque no son disparados manualmente desde la interfaz.

2. Actores del sistema

Actor Descripción Capacidades principales
Colaborador Usuario operativo del centro con acceso al sistema. Iniciar sesión, consultar panel, gestionar adultos mayores, medicamentos e historial de salud.
Administrador Usuario con acceso completo a funciones operativas y administrativas. Todas las capacidades del colaborador más la administración de usuarios y de notificaciones del sistema.
Sistema Aplicación web y servicios backend. Validar credenciales, guardar información, controlar permisos y mostrar mensajes de confirmación o error.

4. Casos de uso detallados

CU-01. Iniciar sesión

Actor principal: Colaborador o Administrador

Objetivo: Acceder al sistema con credenciales válidas.

Precondiciones: El usuario posee correo y contraseña registrados y se encuentra activo.

Disparador: El usuario abre la pantalla de login y presiona "Iniciar sesión".

Flujo principal:

  1. El usuario ingresa su correo electrónico.
  2. El usuario ingresa su contraseña.
  3. El sistema valida formato básico y credenciales.
  4. El sistema crea la sesión y redirige al panel de inicio.

Flujos alternos:

  • Si el correo no es válido, el sistema muestra: "Ingresá un correo electrónico válido."
  • Si el correo o la contraseña son incorrectos, el sistema muestra: "Correo o contraseña incorrectos. Verificá tus datos e intentá de nuevo."
  • Si ocurre un problema de red, el sistema muestra: "Error de conexión. Verificá tu conexión a internet e intentá de nuevo."

Postcondiciones: El usuario autenticado queda en la pantalla /home con sesión activa.

CU-02. Recuperar contraseña

Actor principal: Colaborador o Administrador

Objetivo: Solicitar un enlace para restablecer la contraseña.

Precondiciones: El usuario conoce el correo con el que fue registrado.

Disparador: El usuario selecciona "¿Olvidaste tu contraseña?".

Flujo principal:

  1. El usuario ingresa su correo en la pantalla de recuperación.
  2. El usuario presiona "Enviar link de recuperación".
  3. El sistema procesa la solicitud y muestra la pantalla de confirmación.
  4. El usuario revisa su correo y usa el enlace recibido.

Flujos alternos:

  • Si hay error de conexión, se informa al usuario.
  • Si el enlace es inválido o expira, el flujo debe reiniciarse desde la solicitud de recuperación.

Postcondiciones: El sistema deja al usuario listo para definir una nueva contraseña.

CU-03. Cerrar sesión

Actor principal: Colaborador o Administrador

Objetivo: Finalizar la sesión activa de forma segura.

Precondiciones: El usuario se encuentra autenticado.

Disparador: El usuario presiona "Salir" o "Cerrar sesión".

Flujo principal:

  1. El sistema pregunta: "¿Estás seguro que querés cerrar sesión?"
  2. El usuario confirma la acción.
  3. El sistema elimina la sesión y redirige al login.
  4. El sistema muestra el mensaje "Sesión cerrada correctamente."

Flujos alternos: Si existen cambios sin guardar en formularios, el sistema primero solicita confirmación para descartar cambios.

Postcondiciones: La sesión queda cerrada y el usuario vuelve a la pantalla de acceso.

CU-04. Consultar panel de inicio

Actor principal: Colaborador o Administrador

Objetivo: Visualizar el resumen diario del centro y los medicamentos programados.

Precondiciones: El usuario inició sesión correctamente.

Disparador: El sistema redirige a /home o el usuario selecciona "Inicio".

Flujo principal:

  1. El sistema carga el total de personas registradas.
  2. El sistema calcula quienes tienen medicamentos hoy.
  3. El sistema muestra el total de dosis programadas.
  4. El sistema lista los medicamentos del día por paciente y momento de toma.

Flujos alternos:

  • Si no hay medicamentos para el día, se muestra: "No hay medicamentos programados para hoy."
  • Si la carga falla, aparece una pantalla de error con acción "Reintentar".

Postcondiciones: El usuario obtiene un panorama actualizado del día.

CU-05. Registrar adulto mayor

Actor principal: Colaborador o Administrador

Objetivo: Crear un nuevo registro de adulto mayor en el sistema.

Precondiciones: El usuario tiene sesión activa y permisos operativos.

Disparador: El usuario presiona "+ Nuevo registro" en el módulo Adultos.

Flujo principal:

  1. El usuario completa nombre, cédula, fecha de nacimiento y sexo.
  2. Opcionalmente agrega teléfono, estado civil, pensión IVM, dirección y datos de contacto.
  3. El usuario presiona "Guardar registro".
  4. El sistema valida los datos y almacena el nuevo registro.
  5. El sistema muestra: "Registro guardado exitosamente." y redirige al listado.

Flujos alternos:

  • Si faltan campos obligatorios, el sistema informa: "Los campos Nombre, Cédula, Fecha de nacimiento y Sexo son obligatorios."
  • Si falla la persistencia, se muestra un error de guardado o de conexión.

Postcondiciones: Existe un nuevo adulto mayor disponible para consulta, historial y medicamentos.

CU-06. Consultar y editar perfil de adulto mayor

Actor principal: Colaborador o Administrador

Objetivo: Revisar o actualizar la información de un paciente.

Precondiciones: El paciente existe en el sistema.

Disparador: El usuario selecciona "Ver" en la lista y luego "Editar" si desea modificar datos.

Flujo principal:

  1. El sistema muestra el perfil completo del paciente.
  2. El usuario revisa datos personales, dirección, familiar solicitante y contacto de emergencia.
  3. Si desea editar, abre el formulario correspondiente.
  4. Modifica los campos necesarios y presiona "Guardar cambios".
  5. El sistema confirma con "Registro actualizado exitosamente."

Flujos alternos:

  • Si el paciente fue eliminado o no existe, se muestra el estado "Paciente no encontrado".
  • Si el usuario abandona el formulario con cambios pendientes, el sistema muestra el modal de cambios sin guardar.

Postcondiciones: La información del paciente queda actualizada si el guardado fue exitoso.

CU-07. Eliminar adulto mayor

Actor principal: Colaborador o Administrador

Objetivo: Eliminar un paciente junto con su historial y medicamentos asociados.

Precondiciones: El paciente existe y el usuario confirma la acción.

Disparador: El usuario presiona "Eliminar" en la lista de adultos.

Flujo principal:

  1. El sistema muestra una advertencia de eliminación irreversible.
  2. El usuario selecciona "Sí, eliminar".
  3. El sistema elimina el registro y sus dependencias.
  4. El sistema informa: "[nombre] fue eliminado correctamente."

Flujos alternos:

  • Si el usuario cancela, no se realiza ninguna acción.
  • Si falla la operación, se muestra un mensaje de error y el registro permanece.

Postcondiciones: El paciente deja de estar disponible en el sistema si la eliminación fue exitosa.

CU-08. Gestionar medicamentos

Actor principal: Colaborador o Administrador

Objetivo: Registrar, consultar, editar o eliminar medicamentos asociados a un paciente.

Precondiciones: El usuario seleccionó previamente a un adulto mayor.

Disparador: El usuario entra al módulo "Medicamentos" y elige un paciente.

Flujo principal:

  1. El usuario busca y selecciona una persona.
  2. El sistema muestra sus prescripciones existentes.
  3. El usuario puede agregar un medicamento con nombre, dosis, indicaciones, horarios y días.
  4. El usuario puede editar o eliminar un medicamento existente.
  5. El sistema confirma cada alta, actualización o eliminación.

Flujos alternos:

  • Si no hay persona seleccionada, el sistema no permite agregar medicamentos.
  • Si falta el nombre del medicamento, el sistema rechaza el formulario.
  • Si no se define una combinación válida de días, el sistema solicita corregirla.

Postcondiciones: La pauta de medicación del paciente queda actualizada.

CU-09. Consultar y actualizar historial de salud

Actor principal: Colaborador o Administrador

Objetivo: Mantener la información clínica básica de cada adulto mayor.

Precondiciones: Existe un paciente seleccionado en el módulo Historial.

Disparador: El usuario accede al módulo "Historial" y selecciona una persona.

Flujo principal:

  1. El sistema muestra padecimientos, lesiones, hábitos y operaciones del paciente.
  2. El usuario selecciona "Editar historial".
  3. El usuario modifica la información requerida.
  4. El usuario presiona "Guardar cambios".
  5. El sistema confirma con "Historial actualizado correctamente."

Flujos alternos:

  • Si no existe historial previo, el sistema muestra un estado vacío y permite comenzar la carga.
  • Si el usuario intenta salir con cambios pendientes, se activa el control de cambios sin guardar.

Postcondiciones: El historial del paciente refleja la última información guardada.

CU-10. Configurar notificaciones de medicamentos

Actor principal: Administrador

Objetivo: Activar, apagar o restringir por días el envío del correo automático de medicamentos.

Precondiciones: El usuario autenticado posee rol admin.

Disparador: El administrador ingresa al módulo "Notificaciones" desde el menú lateral.

Flujo principal:

  1. El sistema carga la configuración actual de notificaciones.
  2. El administrador activa o apaga el interruptor "Recibir notificación de medicamentos por correo".
  3. Si la opción está activa, define correo destino y días de envío.
  4. El administrador presiona "Guardar".
  5. El sistema confirma con "Configuración guardada correctamente."

Flujos alternos:

  • Si el correo tiene formato inválido, el sistema muestra: "Ingresá un correo electrónico válido."
  • Si las notificaciones están activas y se selecciona modo específico sin días marcados, el sistema muestra: "Seleccioná al menos un día de la semana."
  • Si la configuración no puede guardarse, el sistema informa: "Error al guardar la configuración."

Postcondiciones: El sistema actualiza la política de envío de correos automáticos; si queda apagada, los reportes diarios se omiten.

CU-11. Administrar usuarios del sistema

Actor principal: Administrador

Objetivo: Crear, editar, activar, desactivar o eliminar cuentas de acceso.

Precondiciones: El usuario autenticado posee rol admin.

Disparador: El administrador presiona el icono de configuración para abrir "Usuarios del sistema".

Flujo principal:

  1. El sistema muestra la lista de usuarios registrados.
  2. El administrador selecciona "+ Nuevo usuario" o "Editar".
  3. Completa nombre, apellidos, correo, rol y estado.
  4. Si se trata de un alta, define una contraseña inicial.
  5. El sistema guarda la información y confirma la acción.

Flujos alternos:

  • Si faltan datos requeridos, el sistema bloquea el guardado.
  • Si la contraseña es demasiado corta, se informa al administrador.
  • El sistema impide dejar la aplicación sin al menos un usuario administrador.
  • El usuario autenticado no puede eliminarse a sí mismo desde el modal.

Postcondiciones: La configuración de accesos queda actualizada según la operación ejecutada.

CU-12. Buscar y seleccionar pacientes

Actor principal: Colaborador o Administrador

Objetivo: Localizar rápidamente a un adulto mayor para ver o modificar su información.

Precondiciones: Existen pacientes cargados en el sistema.

Disparador: El usuario usa el buscador de Adultos, Historial o Medicamentos.

Flujo principal:

  1. El usuario escribe parte del nombre o la cédula.
  2. El sistema filtra o despliega coincidencias en tiempo real.
  3. El usuario selecciona el paciente deseado.
  4. El sistema carga el contexto asociado al módulo actual.

Flujos alternos: Si no existen coincidencias, se muestra un estado vacío o un mensaje equivalente a que no hay resultados.

Postcondiciones: El paciente queda seleccionado para la siguiente operación.

CU-13. Navegar entre módulos con control de cambios sin guardar

Actor principal: Colaborador o Administrador

Objetivo: Cambiar de pantalla sin perder información por accidente.

Precondiciones: El usuario tiene un formulario de adultos o historial con cambios pendientes.

Disparador: El usuario intenta volver, cambiar de módulo o cerrar sesión.

Flujo principal:

  1. El sistema detecta que hay cambios sin guardar.
  2. El sistema muestra el modal "Cambios sin guardar".
  3. El usuario elige "Quedarme" o "Salir sin guardar".
  4. Según la elección, el sistema conserva la edición actual o continúa la navegación solicitada.

Flujos alternos: Si no existen cambios pendientes, la navegación ocurre de inmediato sin modal.

Postcondiciones: El usuario conserva el control sobre sus cambios antes de abandonar la pantalla actual.

5. Reglas generales del sistema

  • Solo usuarios autenticados pueden ingresar a los módulos principales.
  • Solo los administradores pueden gestionar usuarios y la configuración de notificaciones.
  • La eliminación de adultos mayores y usuarios requiere confirmación explícita.
  • La sesión se maneja mediante cookie segura y el sistema actualiza el último acceso al iniciar sesión.
  • Los formularios críticos detectan cambios sin guardar para evitar pérdida accidental de información.
  • El panel de inicio se actualiza automáticamente y usa la lógica diaria de medicamentos del sistema.
  • Las notificaciones de medicamentos pueden apagarse completamente o limitarse a días específicos.
